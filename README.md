# 学业负荷雷达

一个面向大学生的学业任务负荷与截止日期风险分析工具。

## 公网地址

正式提交时请在这里填写已经部署并人工打开验证过的真实地址：

`待部署后填写，例如 https://academic-load-radar.onrender.com`

健康检查地址应为：`<公网地址>/api/health`，返回 `{"status":"ok"}`。部署步骤和提交所需的地址证据见 [`DEPLOYMENT.md`](DEPLOYMENT.md)。

当前是零依赖 MVP：使用 Python 标准库提供 HTTP API、SQLite 数据库和静态 Web 界面。第一版重点验证“任务工时 + 可用时间 + 截止日期”是否能生成可解释的风险提示。

## 运行

在项目目录执行：

```powershell
python -m app.main
```

然后打开 <http://127.0.0.1:8000>。

本地默认数据文件位于系统临时目录。要指定项目内的数据目录，可设置 `ACADEMIC_LOAD_RADAR_DATA`；公网部署必须使用托管平台的持久化目录。

## 当前功能

- 创建、删除和标记完成任务。
- 可直接更新进行中任务的累计投入工时与完成比例。
- 设置工作日/周末可用时间和缓冲比例。
- 根据可用工时、截止日期、优先级与全部待办任务计算组合风险。
- 用 EDF（最早截止期优先）模拟排程，显示建议顺序、预计完成日和截止前工时缺口。
- 为剩余工时预测显示高/中/低可信度，说明当前判断的数据基础。
- 在仪表盘显示下一步行动、高风险任务、预计工时和风险解释，支持筛选与搜索。
- 跟踪任务实际用时，并区分提前、按时和逾期完成。
- 单条补录历史任务，或通过 CSV 批量导入过去的任务。
- 单条录入进行中任务，或通过 CSV 批量导入已经开始但尚未完成的任务。
- 进行中任务支持已投入工时和当前进度，风险分析会按剩余工时估算负荷。
- 查看近 30 天按时完成率、估时偏差和临近截止日期效率变化。
- 根据至少 5 个已完成任务给出缓冲比例调整建议。
- SQLite 持久化，重启后数据仍保留（默认位于系统临时目录；部署时可用 `ACADEMIC_LOAD_RADAR_DATA` 指定持久化目录）。

## 跟踪模式

开启跟踪模式后，点击“标记完成”会记录实际用时。系统会以截止日前 24 小时作为默认的“提前完成”阈值，并在 `/api/insights` 返回滚动窗口统计。临近截止日期的效率提升只作为解释性指标，不会直接替用户降低缓冲比例。

历史任务 API 为 `POST /api/tasks/history`，批量导入 API 为 `POST /api/tasks/import`。CSV 至少需要这些字段：`title`、`course`、`due_date`、`completed_at`、`estimated_hours`、`actual_hours`、`data_precision`；`started_at` 和 `stress_level` 可选。

进行中任务 API 为 `POST /api/tasks/ongoing`，批量导入 API 为 `POST /api/tasks/ongoing/import`。CSV 字段为：`title`、`course`、`due_date`、`started_at`、`estimated_hours`、`spent_hours`、`progress_percent`、`priority`、`data_precision`、`stress_level`。其中 `estimated_hours` 是预计总工时，`spent_hours` 是已经投入的工时，`progress_percent` 必须小于 100。示例文件为 `sample_ongoing_tasks.csv`。

批量处理已填写任务使用 `POST /api/tasks/batch/process`。它会一次重新处理数据库中全部任务，汇总剩余工时、风险分布、组合超载截止日期、排程缺口、最高风险任务和前三项行动建议。前端“任务风险”区域中的“重新计算”按钮会显示这份汇总结果。

更新进行中任务使用 `PUT /api/tasks/{id}`，请求体提供 `spent_hours` 和/或 `progress_percent`，不提供 `status`。当任务第一次出现实际投入或进度时，系统自动记录开始时间。

## 当前预测与组合风险算法

进行中任务的剩余工时预测暂时采用可解释的两部分信号：

1. 根据“已投入工时 / 已完成比例”反推完成该任务的总工时。
2. 使用历史可靠完成记录的 `实际工时 / 预计工时` 中位数，校准当前任务的预计总工时。

两者按进度逐渐增加前者权重，并保留历史效率作为修正，避免刚开始记录时的偶然值影响过大。系统还会依据实际进度是否存在、任务完成比例、可靠历史样本数量与数据精度，给预测标注可信度。

风险分析包含两层：第一层按每个截止日期累计所有未完成任务的剩余工时，再与该日期前扣除缓冲后的总可用时间比较；第二层按 EDF（Earliest Deadline First）逐日分配缓冲后的可用工时，同一截止日期按优先级排序，从而计算每项任务的预计完成日期与截止时未排完的工时。这样多个任务会真实争用同一段时间，不再逐个任务独立计算。当前版本还没有使用大模型做难度判断，后续可以在课程/任务类型维度积累样本后再增加分组效率模型。
